PROPOSED REPOSITORY LAYOUT CHANGES
==================================

Purpose
-------
This document records the recommended repository-layout improvements. These
changes should be made incrementally. They do not require a single wholesale
rewrite.


1. MOVE THE REPOSITORY OUT OF THE HOME-DIRECTORY ROOT
-----------------------------------------------------

Current repository location:

    /home/seancatchpole989/

Recommended location:

    /home/seancatchpole989/projects/education-system/

Target layout:

    /home/seancatchpole989/
    |-- .bashrc
    |-- .cache/
    |-- .claude/
    |-- .codex/
    |-- .config/
    |-- .ssh/
    `-- projects/
        `-- education-system/          Git repository starts here
            |-- .git/
            |-- .github/
            |-- deploy/
            |-- docker/
            |-- docs/
            |-- tools/
            |-- tests/
            |-- src/

            |-- CHANGELOG.md
            |-- LICENSE
            |-- Makefile

    The repository currently shares its root with personal shell, cache and

3. CONSOLIDATE THE APPLICATION ENTRY POINT
------------------------------------------

Replace the two run.py implementations with a package-native launcher:

    src/education_system/
    |-- __init__.py
    |-- __main__.py                    Supports: python -m education_system
    `-- launcher/
        |-- __init__.py
        |-- main.py                    main() and argument parsing
        |-- auth.py
        |-- dispatch.py
        |-- menus.py
        |-- roles.py
        |-- system_switch.py
        `-- systems.py

The installed console entry point should target:

    education-system = "education_system.launcher.main:main"

The root run.py may temporarily remain as a deprecated compatibility shim that
imports education_system.launcher.main.main.

    |-- features/
    |-- governance/
    |-- identity/
    |-- integrations/

Move system-specific routes back to their owning systems:

    platform/delivery/api/university/routes/
        -> systems/university/interfaces/api/routes/

    platform/delivery/api/sixthform/routes/
        -> systems/sixth_form/interfaces/api/routes/

The shared API platform remains responsible for hosting, middleware, router
registration and common protocol support.

8. SIMPLIFY DEPENDENCY FILES
----------------------------

Recommended files:

    education-system/
    |-- pyproject.toml                 Direct dependencies and optional extras
    |-- requirements.lock              Resolved production environment
    `-- requirements-dev.lock          Resolved development environment

Generation flow:

    pyproject.toml
        |-- production resolution -> requirements.lock
        `-- development resolution -> requirements-dev.lock

This should replace the ambiguous combination of requirements.txt,
requirements.lock and requirements-dev.txt once the build and CI workflows
have been updated.


RECOMMENDED IMPLEMENTATION ORDER
--------------------------------

    1. Move the repository to ~/projects/education-system/.
    2. Move docs, tools, tests and var out of program/.
    3. Move program/education_system to src/education_system.
    4. Consolidate the launcher and retire duplicate run.py behaviour.
    5. Move system-specific API routes back into their owning systems.
    6. Reorganise the University system one business domain at a time.
    7. Simplify and document the dependency-lock workflow.

Steps 1-4 provide the largest immediate clarity improvement. Steps 5-7 should
be handled as gradual architectural migrations with tests passing after every
stage.
