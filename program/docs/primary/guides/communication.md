Last Updated: March 2026

## Email

Send emails to parents, staff, and groups from within the system.

### Sending an Email

1. Navigate to Email tab.
2. Select recipients:
   - **Individual** — Search by parent or staff name.
   - **Class** — All parents of pupils in a specific class.
   - **Year group** — All parents in a year group.
   - **Whole school** — All parents or all staff.
   - **Custom group** — Select specific recipients.
3. Enter subject and body text.
4. Attach files if needed (letters, forms, documents).
5. Preview and send.

### Templates

| Template | Use Case |
|---|---|
| Absence notification | Inform parents of unexplained absence |
| Trip letter | Trip details with consent form link |
| Newsletter | Weekly/monthly school newsletter |
| Meeting invitation | Parents' evening, SEND review, etc. |
| General letter | Customisable general communication |

- **Create templates** — Build reusable email templates with merge fields (pupil name, class, date).
- **Edit templates** — Modify existing templates without affecting previously sent emails.

### Bulk Emails

- Send to large groups with automatic personalisation using merge fields.
- The system handles batching to avoid email server limits.
- Track delivery status (sent, failed).

### Key Features

- **Email history** — View all sent emails with date, recipients, and content.
- **Resend** — Resend a previous email to additional recipients.
- **Drafts** — Save emails as drafts to complete later.
- **Scheduled send** — Set a future date and time for the email to be sent.
- Sent emails are automatically logged in the Communication Log.

## Notifications

Manage in-app notifications and system alerts.

### Notification Types

| Type | Triggered By |
|---|---|
| Attendance alert | Pupil absence not yet explained |
| Overdue homework | Homework past due date |
| Policy review | Policy approaching review date |
| DBS expiry | Staff DBS check approaching expiry |
| Consent missing | Outstanding consent forms |
| Assessment due | Assessment window approaching |
| Medical alert | Medication due or care plan update needed |
| System | Backup completed, data export ready, etc. |

### How Notifications Work

- Notifications appear in the notification panel (bell icon in the top bar).
- Unread notifications are highlighted with a count badge.
- Click a notification to navigate to the relevant module and record.
- Mark notifications as read individually or in bulk.

### Notification Settings

- **Per-user preferences** — Each user can configure which notification types they receive.
- **Admin controls** — Admins can set mandatory notifications that cannot be turned off.
- **Quiet hours** — Notifications are suppressed during configured quiet hours.

## Announcements

Publish announcements to the school community.

### Announcement Scope

| Scope | Audience |
|---|---|
| Whole School | All staff and parents |
| Staff Only | Staff members only |
| Year Group | Parents and staff for a specific year group |
| Class | Parents and staff for a specific class |
| Parents Only | All parents (excludes non-parent staff) |

### Creating an Announcement

1. Navigate to Announcements tab.
2. Click New Announcement.
3. Enter title and body text.
4. Select scope (audience).
5. Set display period (start and end dates).
6. Choose priority (Normal, Important, Urgent).
7. Publish.

### Key Features

- **Pinned announcements** — Pin important announcements to the top of the list.
- **Expiry** — Announcements automatically disappear after the end date.
- **Edit/Withdraw** — Edit a published announcement or withdraw it early.
- **History** — View all past announcements with dates and audiences.
- **Dashboard display** — Current announcements appear on the dashboard for relevant users.

## Calendar

Manage the school calendar including term dates, events, and INSET days.

### Calendar Event Types

| Type | Colour Code | Examples |
|---|---|---|
| Term Dates | Blue | Start/end of Autumn, Spring, Summer terms |
| Half Terms | Light Blue | October, February, May half terms |
| INSET Days | Grey | Staff training days (non-pupil) |
| School Events | Green | Sports day, harvest festival, nativity |
| Trips | Orange | Educational visits (linked from Trips module) |
| Parents' Evening | Purple | Consultation evenings |
| Assessments | Red | SATs week, assessment windows |
| Meetings | Yellow | Staff meetings, governor meetings |
| Deadlines | Red | Census deadline, report deadline |

### Key Workflows

- **Add event** — Select date(s), enter title, choose type, add description and location.
- **Recurring events** — Set weekly or termly recurring events (e.g., weekly assembly, termly staff meeting).
- **Year planner** — View the full academic year on a single page with all event types.
- **Monthly/weekly view** — Switch between monthly, weekly, and daily calendar views.
- **Filter** — Show/hide event types using the colour-coded filter.
- **Export** — Export calendar as iCal format for import into personal calendars.

### Term Date Management

- Define term start and end dates for the academic year.
- Mark half-term holiday dates.
- Set INSET days (the system excludes these from attendance calculations).
- Term dates feed into the attendance module to calculate the total sessions expected.

## Parents' Evening

Manage parents' evening bookings and scheduling.

### Setup Workflow

1. **Create event** — Set the parents' evening date(s), start time, end time, and appointment duration (e.g., 10 minutes).
2. **Teacher availability** — Each teacher marks their available time slots. Teachers can block slots for breaks.
3. **Open bookings** — Activate the booking window. Set an opening date/time for parents to begin booking.
4. **Parent booking** — Parents select their preferred time slot for each teacher they need to see.
5. **Close bookings** — Close the booking window at the configured deadline.
6. **Generate schedules** — Produce a schedule for each teacher showing their appointments.

### Booking Features

| Feature | Description |
|---|---|
| Slot duration | Configurable (5, 10, 15 minutes) |
| Buffer time | Gap between appointments (e.g., 2 minutes) |
| Multiple children | Parents with siblings can book consecutive slots |
| Clash prevention | System prevents parents from double-booking themselves |
| Reminders | Automated reminder sent to parents before the evening |

### Key Features

- **Live view** — View real-time booking status showing booked, available, and blocked slots.
- **Admin override** — Admins can book, move, or cancel appointments on behalf of parents.
- **No-show tracking** — Mark parents who did not attend. Follow up with alternative arrangements.
- **Reports** — Booking completion rates by class. List of parents who have not booked.

## Communication Log

Maintain a comprehensive record of all communications with parents and carers.

### What Is Logged

| Source | Auto-Logged | Manual Entry |
|---|---|---|
| Emails sent from system | Yes | — |
| Phone calls | — | Yes |
| Face-to-face meetings | — | Yes |
| Letters sent | — | Yes |
| Text messages | Yes (if integrated) | Yes |
| Parents' evening notes | — | Yes |

### Manual Log Entry

1. Navigate to Communication Log tab.
2. Click Add Entry.
3. Select the pupil (the communication is linked to their record).
4. Choose communication type (phone call, meeting, letter, other).
5. Enter date, summary, and outcome.
6. Record any agreed actions.
7. Save.

### Key Features

- **Pupil-linked** — All communications are linked to the relevant pupil record. View a pupil's complete communication history from their profile.
- **Search** — Search by pupil, parent, date range, communication type, or keyword.
- **Follow-up actions** — Record agreed actions with deadlines. Track completion.
- **Staff attribution** — Each entry records which staff member made the communication.
- **Chronological view** — View all communications for a pupil in date order, providing a full picture for SEND reviews, pastoral meetings, or safeguarding chronologies.
- **Export** — Export communication history for individual pupils or groups.

### Best Practice

- Log all significant communications promptly.
- Include the key points discussed and any outcomes or agreed actions.
- Link to relevant modules (pastoral, SEND, behaviour) where appropriate.
- Communication logs form part of the evidence base for Ofsted, SEND reviews, and safeguarding.

## Cross-System Messaging

Primary school staff often need to coordinate transitions with the
receiving secondary school (Year 6 → Year 7 transfers, SEND handovers,
safeguarding chronologies, etc.). The **Cross-System Messaging** feature
is embedded directly into the Primary School Email screen and Email CLI
so you don't have to leave email to talk to staff in Secondary, College,
or University.

### Where to find it

| Interface | Location |
|-----------|----------|
| GUI | **Communication → Email**, then the **Cross-System** tab |
| CLI | **Communication → Email → 3) Cross-System Messages** |

### What it does

| Tab / option | Purpose |
|---|---|
| Inbox | Messages other systems' staff have sent to you. Sender, system, subject, related pupil, date, read state. |
| Sent | Messages you've sent out to other systems. |
| Compose | Pick the target system (Primary / Secondary / College / University), then a recipient from that system's staff list, optionally tag a pupil name, then enter subject + body. |

Messages are stored centrally in `auth.db` (`cross_system_messages`
table) so the recipient sees them from whichever system they log into.

### Service reference

| Method | Purpose |
|--------|---------|
| `InterSystemMessagingService.send_message` | Send a message to a staff member in another system |
| `InterSystemMessagingService.get_inbox` | Retrieve messages received from other systems |
| `InterSystemMessagingService.get_sent` | Retrieve messages sent to other systems |
| `InterSystemMessagingService.get_staff_list(system)` | List staff in a target system for the recipient picker |
| `InterSystemMessagingService.search_messages` | Search inbox + sent by subject, body, or pupil name |

The reusable GUI panel lives in
`education_system.shared.messaging.cross_system_panel` and the CLI in
`education_system.shared.messaging.cross_system_cli`.

## Idle / inactivity auto-logout

The Primary School GUI and CLI both auto-log-out after **30 minutes of
inactivity** to reduce the risk of an unattended terminal exposing pupil
data — particularly important on shared classroom or staffroom machines.

| Interface | How activity is tracked |
|-----------|-------------------------|
| GUI | Mouse motion, key presses, mouse buttons, and scroll-wheel events on the main window reset the idle timer. |
| CLI | The menu prompt is wrapped in a `SIGALRM` watchdog that fires after 30 minutes of no input. |

When the timeout fires, the GUI shows a `Session Expired` warning then
returns the user to the universal login screen; the CLI prints
`⚠ Logged out after 30 minutes of inactivity.` and exits cleanly.

To change the default, edit the `attach_idle_timeout(self, ..., timeout_minutes=30)`
call in `primary_school/main_gui.py` or the `enable_idle_timeout(30, ...)`
call in `primary_school/cli/cli_main.py`.

See `docs/primary/security/SESSION_TIMEOUT.md` for the full
configuration and security rationale.
